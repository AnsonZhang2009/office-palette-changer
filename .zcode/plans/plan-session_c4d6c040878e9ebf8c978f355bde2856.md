## Color roles (your decision: auto-detect, explicit flags override)

Positional colors are classified by lightness: very dark (L ≤ 22%) → text, very light (L ≥ 90%) → background, everything else → accents in the order given (max 6; extras warned and ignored). Explicit flags claim a role first, so `--text`, `--background`, and repeatable `--accent` always win; a positional that would have taken an already-claimed role falls back to being an accent. If no accent is supplied at all, one is synthesized from the text/background hue.

## Palette derivation (deterministic — same inputs always give the same theme)

All math is done in HSL plus WCAG relative luminance, hand-written in a new `internal/palette` package (no dependencies).

- **Neutrals** derive from the primary accent's hue: `dk1` = near-black tint (S 18%, L 13%), `lt1` = near-white tint (S 25%, L 97.5%), `dk2`/`lt2` = lighter/darker steps of those. A contrast guard pushes text and background apart until they reach ≥ 7:1.
- **Missing accents** are generated by rotating the hues of the supplied accents (±30°, complementary ±150°, …), skipping candidates too close to an existing accent, and clamping lightness so they read on the background. User-supplied accents are **never altered** — if one has poor contrast you get a warning, not a silently changed brand color.
- **Links**: `hlink` = the accent closest to blue (or accent 1 darkened), `folHlink` = that hue shifted toward purple, mirroring Office's blue→purple convention.
- **`--dark`**: light text on a dark background, with the `midnight` pattern baked in — an `@word { :root {…} }` override keeps Word body text dark-on-white, and `@ppt { background: var(--lt1) }` gives decks the dark canvas.
- The generated theme also includes sensible `@word` heading styles (h1 bold accent 1, h2 bold dk2, h3 bold accent 2), skippable with `--no-headings`.

## Command details

```
ostyle palette <name> <color...> [--text hex] [--background hex] [--accent hex]...
                               [--dark] [--heading-font F] [--body-font F]
                               [--no-headings] [--print] [--here] [--force]
ostyle palette -i              guided wizard (same flags accepted as defaults)
```

`--print` writes the CSS to stdout instead of a file. The written `.css` carries a `/* generated by: ostyle palette … */` comment so a theme is reproducible from its header, and uses the friendly `--text`/`--background` aliases for hand editing.

## Also included (the two fixes from your last question)

- `ostyle list` says "(not created yet — `ostyle palette` or `ostyle new` creates it)" when the user theme dir doesn't exist.
- `ostyle new <name> --copy <theme>` clones any built-in or user theme into your theme dir for tweaking.
